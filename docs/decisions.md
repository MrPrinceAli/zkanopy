## Phase 1 — Circuit (2026-09-18)

| # | Decision | Reason |
|---|---|---|
| 1.1 | One root-level `package.json` hosts the Node tooling for `circuits/` (and later `oracle/*.js`); `frontend/` gets its own in Phase 4. `npm test` at the root runs the circuit tests. | Simplest layout that keeps `-l node_modules` working for circom and lets the oracle reuse `circomlibjs` without a second install. |
| 1.2 | Merkle helpers live in `packages/merkle/index.js` (CommonJS, BigInt values): `buildTree`, `getPath`, `computeRoot`. Zero-only subtrees reuse cached per-level zero nodes. | PRD 5.5 offers `packages/merkle/` as the shared location; the zero-node cache makes the sparse depth-16 test tree instant and will keep the browser path lookup cheap. |
| 1.3 | Path convention: `pathIndices[i]` = bit *i* of `leafIndex` (0 = running node is the left child), `pathElements[i]` = sibling at level *i*. Zero leaf = `Poseidon(0,0,0)`. | Matches the Tornado/Semaphore `MerkleTreeChecker` pattern named in PRD 5.3; `frontend/src/lib/merkle.ts` must port it unchanged. |
| 1.4 | `pragma circom 2.1.0`; compiled with circom 2.1.9, default optimisation. Result: **5 050 constraints**, 1 output + 6 public inputs + 36 private inputs. | Any 2.1.x/2.2.x compiler accepts the pragma. |
| 1.5 | Range check implemented as an `InRange64` sub-template: `Num2Bits(64)` on `x`, `lo`, `hi`, then `LessEqThan(64)` and `LessThan(64)`. Lower edge inclusive, upper edge exclusive. | Exactly PRD 5.3 constraint 1; bounding all three compared values is what makes circomlib's comparators sound. |
| 1.6 | Public signal order **verified** from `build/public.json`: `[nullifier, root, season, exporter, lat0S, lon0S, stepS]`. Frozen from now on (PRD 12.1). | Circom orders outputs first, then public inputs in declaration order; the template declares them in PRD order. |
| 1.7 | Test/fixture grid is synthetic: 4×4 cells, origin 4.0 N / 96.0 E (`lat0S=94000000`, `lon0S=276000000`), `stepS=900`, depth 16, season 2026, exporter = anvil account #0 (`0xf39F…2266`). Clean cell (0,0), loss cell (0,2). | Small enough for fast tests, realistic enough to exercise the fixed-point maths. `contracts/test/fixtures/proof_ok.json` carries the matching `grid` block so `Registry.t.sol` can register it verbatim. |
| 1.8 | Phase-2 contribution uses fresh `openssl rand` entropy on every `build.sh` run, so zkey / `verification_key.json` / `Groth16Verifier.sol` form a matched set that changes on rebuild. | Honest single-party contribution (PRD 5.3 accepts one). Consequence: after any rebuild, redeploy the verifier and re-copy the zkey to the frontend. The final zkey is only **2.9 MB**; whether to ship it via git or a download is decided in Phase 4. |
| 1.9 | Tests use Node's built-in `node:assert/strict` and `circom_tester` (wasm); mocha runs with `--exit` because snarkjs keeps worker threads alive. | No chai dependency (v5 is ESM-only); fewer moving parts. |

## Phase 2 — Contract (2026-09-18)

| # | Decision | Reason |
|---|---|---|
| 2.1 | Foundry project rooted at `contracts/` with `solc = "0.8.24"` pinned and `forge-std` v1.16.2 as a git submodule (`contracts/lib/forge-std`). | PRD 5.1 says `^0.8.24`; pinning keeps bytecode reproducible. Submodule is the Foundry norm (`git clone --recurse-submodules`, or `forge install` after cloning). |
| 2.2 | `Registry` ids (`gridId`, attestation `id`) start at 1; 0 means "none". `owner` is immutable (deployer); `oracle` defaults to the deployer and is changeable via `setOracle`. | Matches PRD 5.4 ("oracle = alamat deployer; setOracle onlyOwner"); no ownership transfer since PRD does not ask for it. |
| 2.3 | `attest` checks run in the PRD order: grid/root → exporter → proof → nullifier. `Attestation.timestamp` and `Grid.publishedAt` are set from `block.timestamp`; `Grid.version` is stored as supplied by the oracle. | PRD 5.4 steps 1–5 verbatim. |
| 2.4 | Extra input-validation errors beyond the four PRD names: `NotOwner`, `NotOracle`, `ZeroAddress`, `InvalidGrid` (root/stepS/cols/rows = 0), `UnknownGrid`, `UnknownAttestation`, `SeasonOutOfRange` (season must fit `uint32`). The four PRD error names are unchanged and now frozen (PRD 12.1). |
| 2.5 | Contract tests load `test/fixtures/proof_ok.json` via `vm.readFile` + `stdJson` (`fs_permissions` read-only on `./test/fixtures`). A tampered *public signal* with valid points costs the normal ~290 k gas. | Inherent to the snarkjs verifier; not modified. | 2.7 | `Deploy.s.sol` uses `vm.startBroadcast()` with the sender supplied on the CLI (`--private-key`), not `vm.envUint`. Deployment addresses are recorded in `frontend/src/config.ts` and README. | Keeps secret parsing out of Solidity; one documented command. |

## Phase 3 — Oracle & AI (2026-09-18)

| # | Decision | Reason |
|---|---|---|
| 3.1 | AOI = Gayo highlands around Takengon, Central Aceh (arabica coffee smallholders): origin 4.55° N / 96.75° E, 200 × 200 cells, `step_deg` 0.0009 (`stepS` 900), depth 16. Grid name `gayo-aceh-coffee`, version 1. | PRD 5.5 offers Sulawesi or Aceh; this landscape mixes coffee plots, forest and a lake, so both labels occur (6.5 % of cells have post-2020 Hansen loss). |
| 3.2 | Rasters fetched synchronously with `ee.Image.getDownloadURL` (GeoTIFF, EPSG:4326, 30 m) instead of Drive export tasks. Cloud mask: SCL ∈ {1,3,8,9,10,11} and QA60 bits 10/11; scenes with `CLOUDY_PIXEL_PERCENTAGE ≥ 80` dropped; annual median NDVI. | 669 × 669 px per raster ≈ 1.5 MB, far below the download limits; the whole export takes ~30 s and needs no Drive round-trip. |
| 3.3 | Hansen `lossyear` is read **without** honouring the GeoTIFF nodata tag (GEE marks 0 as nodata, but 0 means "no loss"). NDVI rasters honour nodata → NaN. Regression test `test_read_raster_keeps_hansen_zeros`. | Caught during the first real run: masking 0 would have labelled ~92 % of cells as missing/loss. |
| 3.4 | Per-cell aggregation maps every pixel centre to `row*cols+col` with the same fixed-point maths as the circuit (`round((lat+90)*1e6)`, `floor_divide`), so rasters with different pixel grids can be combined. Cells with no Hansen pixels are labelled loss. | Exact consistency with the circuit's range check; conservative default for missing data. |
| 3.5 | `02_build_grid.py --synthetic` generates a seeded random grid (~10 % loss) as the PRD Section 10 fallback. The published grid uses real data; the flag is only for reproduction without GEE access. | Keeps later phases unblocked for anyone without an Earth Engine account. |
| 3.6 | AI QC: `RandomForestClassifier(n_estimators=300, min_samples_leaf=2, class_weight="balanced", random_state=42)`, stratified 80/20 split, features `[ndvi_2020, ndvi_2025, dndvi]`, median imputation. Scores are computed for every cell (training cells included) because the output is a QC label, not an evaluation. **Result:** accuracy 0.8695, F1(loss) 0.216, recall(loss) 0.275; 2 266 disagreements; 1 887 Hansen-clean cells blocked, 379 Hansen-loss cells stay loss. | Honest outcome: annual-median NDVI at ~100 m cannot see one cleared 30 m pixel out of eleven. `class_weight="balanced"` deliberately favours recall on loss, which under the `hansen ∧ ai` rule only ever removes clean cells — the conservative behaviour PRD 7 asks for. |
| 3.7 | `tree.json` (3.22 MB) = `{schema, name, version, generatedAt, depth, cols, rows, lat0S, lon0S, stepS, root, zeroLeaf, labels, leaves}`. `labels` is a 40 000-char row-major `'0'/'1'` string so the client can show clean/loss without hashing; `leaves` holds only `rows*cols` entries, the rest are `zeroLeaf`. | Under the 10 MB limit (PRD 5.6); the client rebuilds inner nodes with `packages/merkle` semantics. |
| 3.8 | On-chain `Grid.metadataURI` = `sha256:<hex of frontend/public/data/metadata.json>`. That file (committed, served at `/data/metadata.json`) records datasets, AI metrics, the labelling rule and `sha256(tree.json)`. `config.yaml: metadata_uri` can override it when a new grid version is registered with a public URL. | No frontend URL or IPFS pinning exists yet; a content hash is verifiable by anyone and avoids a dead link on-chain. |
| 3.9 | **Publication record:** `gridId` 1, tx `0xbe5ebc5c…4fa1`, block 46964085, gas 212 960, root `0x09f5f689…ad7a`, `publishedAt` 1789696458. `05_publish_root.js` is idempotent (looks up `RootRegistered` logs by root before sending) and retries reads, because the public RPC's nodes can lag a block behind each other (the first run hit `UnknownGrid` on `getGrid` right after the receipt). | One root per grid version; re-running the pipeline never double-registers. |
| 3.10 | Root `package.json` also carries `viem` and `dotenv` (runtime deps) for `05_publish_root.js`; `npm test` now covers `oracle/tests/*.test.js`, `python -m pytest` covers `oracle/tests/test_*.py`. | Single Node install for circuit + oracle tooling (decision 1.1). |

## Phase 4 — Farmer frontend (2026-09-18)

| # | Decision | Reason |
|---|---|---|
| 4.1 | `frontend/` written by hand (no `create-vite`) as its own npm package; npm resolved Vite 8, React 19, wagmi 3, viem 2, react-leaflet 5, TypeScript 7. Tests use vitest (excluded from the app `tsc` pass). | The directory already held `config.ts` and `public/data/`; the scaffolder refuses non-empty targets. |
| 4.2 | Client Merkle paths use **poseidon-lite** (pure JS, ~0.15 ms/hash) plus `frontend/public/data/checkpoint.json` = the 256 nodes of tree level 8. | 4.3 | `frontend/public/zk/` (wasm + zkey) is **gitignored**; `frontend/scripts/sync-zk.mjs` (runs on `predev`/`prebuild`) copies from `circuits/build/` or downloads from `ZKEY_URL`/`WASM_URL`. | PRD hard rule 12.4: never commit the final zkey. Vercel will use `ZKEY_URL` (Phase 6). |

## Phase 5 — Exporter, verify & regulator (2026-09-18)

| # | Decision | Reason |
|---|---|---|
| 5.1 | `/exporter` lists attestations from `attestationsOf(address)` + a multicall of `getAttestation` (timestamps come from the struct); `Attested` logs are fetched only to attach tx hashes and are optional. Log queries use one call over the whole range and halve it recursively when the RPC rejects (`lib/logs.ts`, same logic in `06_claim_anomaly.py`). | Public RPCs cap `eth_getLogs` ranges; Base produces ~43 k blocks/day so the deploy→head range grows fast. The table never depends on logs. |
| 5.2 | `/exporter` also works without a wallet by typing an exporter address (read-only). | Attestations are public data; it lets auditors look and lets the flow be tested headlessly (US3). |
| 5.3 | DDS export builds **one document per (commodity, season)** from the selected rows (`lib/dds.ts`), file name `dds-<HS>-<season>-<addr6>.json`, `operator.eori` from an optional input (default `PLACEHOLDER`), `txHash: null` when logs were unavailable. Schema exactly PRD 5.7; README states it is a conceptual mapping, not the TRACES format. | A DDS covers one commodity and season; mixed selections are split instead of rejected. |
| 5.4 | `/verify/:id` reads `getAttestation` + `getGrid` (no logs needed) and tries the log for the tx hash; `sha256:` metadata URIs link to `/data/metadata.json`; `UnknownAttestation` renders as "does not exist". | US4 without a wallet. |
| 5.5 | `06_claim_anomaly.py` talks plain JSON-RPC via `requests` (`eth_getLogs`, `eth_getBlockByNumber`) and decodes `Attested` by hand (topic hash hard-coded; event frozen since Phase 2) — no web3.py. | No guaranteed web3.py wheels for Python 3.14; the decoding is three fixed-size words. |
| 5.6 | Features per exporter: `n_claims`, `max_claims_per_hour` (busiest 60-min window), `near_ratio` (share of claims ≤ 300 s after the previous one), `peers_same_season` (distinct other exporters active in the same season(s)); `IsolationForest(n_estimators=200, contamination="auto", random_state=42)`; `risk_score` = min-max scaled `-score_samples` (1 = most anomalous in the set); `reasons` from median-relative thresholds. Fewer than 2 exporters → status `insufficient_exporters`, all zero. | PRD 5.6 /regulator #1 feature list; scores are relative by design and say so in the UI. |
| 5.7 | Demo wallets (keys in `.env`, testnet only, funded from the project wallet): ROGUE `0x0DB5…49F0` (25 cocoa claims in 65 s), EXPORTER_A `0x959F…3F25` (2 coffee claims, 20 s apart), EXPORTER_B `0xFD12…F456` (3 palm-oil claims). Seeded with `scripts/seed-demo.mjs` from row 150 upwards, all genuine proofs. | IsolationForest needs peers to isolate against; two ordinary exporters plus the project wallet give it four points. |
| 5.8 | **Result record:** 31 `Attested` events (ids 1–31, blocks 46963452–46965268). Risk: ROGUE **1.00** ("25 claims vs. a median of 2.5; burst: 25 claims within one hour; 100 % of claims within 5 min"), project wallet 0.64 (single claim — the other outlier in a 4-point set), EXPORTER_B 0.10, EXPORTER_A 0.00. `frontend/public/data/risk.json` committed; re-run step 06 to refresh. | Rogue wallet visibly on top, as PRD 5.6 /regulator #3 requires. With more real exporters the mid scores will settle. |
